02 Data Architecture

Four-layer stack: Source → Transform → Analytics → Presentation

  • Source: CSV exports from order systems, payments, product and geo lookups (CSV, SFTP)
  • Transform: `northcommerce_preprocess.py` (date parsing, city normalisation, delivery_status imputation, GMV caps) → Parquet/DuckDB (Python, DuckDB)
  • Analytics: `northcommerce_pipeline.sql` (CTEs & views for weekly trends, RFM, CLV, anomaly flags) (SQL)
  • Presentation: `streamlit_dashboard.py` and Power BI flat tables (`v_pbi_*`) (Streamlit, Power BI)

Notes: delivery_status nulls are filled with city-mode; city normalisation uses a canonical regex-based map (50 entries). See the pipeline for details.

03 Analytical Modules

  1. KPIs & Health — weekly revenue, orders, AOV, GM% by region. Recruiter reads: can deliver executive-ready KPI cards in hours.
  2. Regional Drill-downs — state → city weekly trends & alerts. Recruiter reads: can identify which city needs ops attention.
  3. Product Performance — category & SKU revenue + margin. Recruiter reads: identifies top SKUs for promotions.
  4. Customer Analytics (RFM) — five segments with CLV and retention. Recruiter reads: builds targeted reactivation lists.
  5. Anomaly Detection — z-score + IQR flags, severity classifier. Recruiter reads: early-warning system for regional drops.
  6. Win‑back ROI — deterministic & Monte Carlo winback model. Recruiter reads: quantifies cost to recover revenue loss.

05 Data Pipeline (5 steps)

  1. Ingest: load CSVs (`data/merged_orders.csv`, payments, products, customers)
  2. Validate: PK dedup, date range filter, negative GMV removal
  3. Clean: city normalisation, fill `delivery_status` by city-mode, KNN impute `Quantity`
  4. Enrich: add time features, festival windows, region flags
  5. Export: Parquet / DuckDB + aggregated CSVs for Power BI

Tools: Python (Pandas, scikit-learn), DuckDB/Parquet, SQL CTEs
